# 탄만큼 QA 노트

테스트 방법: `python3 -m http.server`로 로컬 서버에 띄운 뒤(`.claude/launch.json`에 설정, 이번 회차 실제 포트는 8935), 브라우저 콘솔에서 전역 함수(`isRouteEligible`, `calcMatchScore`, `calcFinalRouteAndFare`, `splitProportional`, `fetchRoute`, `renderPodDetail` 등)를 직접 호출했다.

`file://`로 열면 카카오맵 SDK와 카카오모빌리티 API가 모두 막힌다(도메인 미등록 / CORS). 반드시 localhost 서버로 띄워야 한다.

## 상시 점검

콘솔에서 `runSelfCheck()`를 실행하면 요금 분배 불변식과 하차지점 회귀를 한 번에 확인한다.
캐시가 비어 있을 때(콜드)와 팟이 생성된 뒤(웜) 모두 통과해야 한다.

```
runSelfCheck()  // → {passed: true, fails: []}
```

## 요금 모델: 경로는 하나다

택시는 **출발지 → 팟장 목적지** 경로 하나만 달린다. 참여자는 그 경로 위에서 내리고, 하차지점부터 목적지까지는 걸어간다.
택시가 각자의 하차지점으로 우회하지 않는다.

이전 구현은 하차지점들을 경유지로 넣어 길찾기 API를 다시 불렀고, 그래서 택시가 지그재그로 돌았다.
포항역→영일대 팟이 직행 9,100원인데 총액이 14,000원까지 뛰었다. 지금은 그런 일이 없다.

계산 방식:

- 총액 = 출발지→팟장 목적지 직행 요금 (API 호출 1회)
- 하차 순서 = 각 하차지점을 경로선에 투영한 진행거리 순
- 구간 거리 = 인접한 두 하차지점의 진행거리 차이
- 구간 요금 = 총액을 구간 거리 비율로 분배
- 개인 부담금 = 자기가 타고 있던 구간들의 요금을, 그 구간에 함께 탄 인원수로 나눈 값

`runSelfCheck()`가 검사하는 핵심 불변식은 **팟 총액 == 직행 요금**이다. 이 값이 어긋나면 어딘가에서 우회가 생긴 것이다.

## 이번 회차에 고친 버그

1. **경로 밖 목적지를 가진 참여자가 출발지에서 하차**로 계산됐다.
   `isRouteEligible`이 출발지에 대해 항상 `true`를 돌려주기 때문에 출발지가 언제나 하차 후보로 남았고,
   그 결과 "포항역 하차 · 도보 65분 · 0원" 같은 값이 화면에 그대로 나왔다.
   출발지는 목적지가 실제로 출발지일 때만 후보로 두도록 고쳤고, 후보가 없으면 팟장 목적지까지 타고 가 걷는다.

2. **하차 순서가 출발지 직선거리 기준**이라 실제 주행 순서와 어긋났다.
   출발지→각 하차지점의 실제 주행거리로 정렬하도록 바꿨다.
   (경로선에 투영해 순서를 매기는 방식도 시도했으나, 경로에서 벗어난 지점이 항상 끝으로 밀려 순서가 뒤집혔다.)

3. **구간 요금 가중치에 기본요금이 구간마다 중복**됐다.
   택시는 전체 운행에 기본요금을 한 번만 매기는데 구간마다 4,800원이 붙어 짧은 구간이 과대평가됐고,
   거의 같은 지점에 내리는 세 명의 부담금이 1,884원과 8,145원으로 벌어졌다.
   실제 주행거리를 가중치로 바꾼 뒤 4,577 / 4,413 / 4,510원으로 정리됐다.

## 경로 우선순위를 DISTANCE로 고정한 이유

처음엔 `priority=RECOMMEND`로 불렀는데, 실시간 교통을 반영하다 보니 같은 출발지·목적지인데도 호출 시점마다 다른 경로가 돌아왔다.
포항역→환호공원이 한 번은 내륙(10.6km), 다른 때는 해안(8.2km)으로 나왔고, 영일대해수욕장까지의 이탈 거리가 1,964m와 468m로 갈렸다.
경로 적합성(`ROUTE_CORRIDOR_M = 500`)을 이 거리로 판정하므로, 같은 팟이 접속 시점에 따라 참가 가능/불가로 뒤집혔다.

`priority=DISTANCE`로 고정한 뒤 4회 반복 호출에서 거리·요금·소요시간이 전부 동일하게 나왔다(8,401m / 11,400원 / 1,286초).
경유지가 있는 다구간 경로에서도 같았다.

한 가지 짚어둘 것: 화면에 잠깐 다른 총액이 스치는 경우가 있는데 이건 API가 흔들리는 게 아니라
최종 다구간 경로 응답이 도착하기 전까지 추정 요금을 보여주기 때문이다(설계상 의도). 캐시가 차면 `totalFare === API 요금`으로 정확히 일치한다.

## 아직 시험 안 한 갈래

- `dissolvePod`(팟장 취소 → 해체 → 재매칭 복귀) 경계 케이스. 특히 해체 시점에 다른 참여자가 이미 다른 팟에 참가한 동시성 상황.
- 길찾기 API가 실패했을 때의 폴백 경로. 코드상 직선 렌더 + 추정 요금으로 내려가고 범례/안내 문구도 바뀌지만, 실제 API 장애를 재현해 확인하지는 않았다.
- 화면 스크린샷 기반 시각 검증. 이번 회차 미리보기 창이 스크린샷을 정상 크기로 뱉지 못해 지도는 타일 로드 수와 범례 문구로만 확인했다.
