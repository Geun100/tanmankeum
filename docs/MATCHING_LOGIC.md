# 탄만큼 핵심 로직 정리 (해커톤 Q&A 대비)

전부 `index.html` 안 순수 함수들이다. 서버 로직이 아니라 클라이언트에서 계산하고,
확정 시점에만 그 결과를 DB(Supabase)에 반영하는 구조.

---

## 1. "매칭이 된다"는 건 정확히 뭘 기준으로 판단하나?

한 사람(user)이 한 팟(pod)에 낄 수 있는지는 **5개 조건을 전부 통과해야** 성립한다
(`calcMatchScore`, index.html:1230).

| 조건 | 기준 | 왜 이 기준인가 |
|---|---|---|
| ① 출발지 근접 | 내 출발지 ↔ 팟 출발지 직선거리 ≤ **300m** | 이름이 달라도("포항역"/"포항역 앞") 실제로 걸어서 만날 수 있으면 매칭 대상. 정확한 합류 지점은 채팅으로 조율 |
| ② 동성 | 팟 안 전원과 내 성별 동일 | 성별은 최초 가입 시 잠기고 이후 못 바꿈(허위입력 방지) |
| ③ 시간 | 내가 고른 시간 대비 팟 출발이 **60분 이상 이르면** 탈락 | 이미 놓친 팟은 안 보여줌. 반대로 내 시간보다 늦게 출발하는 건 얼마든 허용(기다렸다 타면 됨) |
| ④ 도보 10분 캡 | 나를 포함해 **참가자 전원**이 각자 하차지점→실제 목적지까지 도보 10분 이내 (`allWalkable`, 1205) | 매칭 성립의 최종/실질적 기준. 아래 2번 항목의 "경로 위에 있는가"보다 이게 진짜 판정 기준 |
| ⑤ 경로 적합(보조) | 도로 경로 있으면 경로선에서 500m 이내(`ROUTE_CORRIDOR_M`) + 팟장 거리의 1.15배 이내, 없으면 각도차 25도 이내(`ANGLE_THRESHOLD_DEG`) | 정류장 후보를 좁히는 사전 필터용. 실제 성립 여부는 ④가 최종 결정 |

다섯 개를 AND로 걸어 `eligible`이 정해지고, `eligible=false`면 그 팟은 애초에 추천 목록에 안 뜬다
(index.html:2539, 2543 — 정원 다 찬 팟/경로 밖 팟/모집중 아닌 팟도 같이 걸러냄).

## 2. 매칭 점수(100점 만점)는 어떻게 계산되나?

성립 여부(eligible)와 별개로, 추천 순위를 매기는 점수가 따로 있다 (`calcMatchScore`).

```
총점 = 출발지근접(30) + 목적지경로적합(30) + 실경로성립(25) + 시간차(10) + 인원조건(5)
```

- **출발지근접 30점**: `max(0, 30 - 200m당 1점)` — 가까울수록 만점
- **목적지경로적합 30점**: 팟 출발지 기준 "팟장 목적지 방향"과 "내 목적지 방향"의 각도차를 0~30점으로 환산(`bearing`+`angleDiff`). 방향이 정반대면 0점
- **실경로성립 25점**: 위 1번 표의 5개 조건이 전부 참이면 25점, 하나라도 걸리면 0점(all-or-nothing)
- **시간차 10점**: `max(0, 10 - 출발시간차(분)/6)` — 6분당 1점 감점
- **인원조건 5점**: 내가 원하는 인원수와 팟 목표 인원수 차이 — 0명차=5점, 1명차=3점, 2명차=1점, 3명차 이상=0점

## 3. 거리/방향은 실제로 어떻게 계산하나? (좌표 기하학)

외부 지도 SDK 없이 순수 수학으로 처리한다.

- **직선거리**: Haversine 공식 (`dist`, 996) — 지구를 구로 근사해 두 위경도 사이 실거리(m) 계산
- **방위각**: `bearing`(1003) — A에서 B를 바라보는 각도(0~360도), atan2 기반 표준 공식
- **경로선 위 투영**: 카카오 길찾기로 실제 도로 폴리라인(path)을 받아두면,
  - `nearestPointOnPath`(1210): 좌표에서 경로선까지 최단 지점과 거리
  - `progressAlongPath`(1091): 그 지점이 경로 시작점에서 몇 m 지점인지(=주행 순서로 씀)
  - `distToPath`(1111): 좌표-경로선 최단거리
  둘 다 위경도를 로컬 평면(m 단위)으로 근사 변환해서 계산 — 수 km 범위에선 오차 무시 가능
- **경로가 아직 없을 때(폴백)**: 직선 각도차(`angleDiff`)로만 근사 판정

## 4. 하차지점은 어떻게 정해지나?

`recommendDropOff`(1142) 로직:

1. 내 목적지 = 팟장 목적지(trunk)면 → 무조건 종점 하차, 도보 0분 (별도 분기로 먼저 처리, 1147)
2. 실제 도로 경로가 있으면 → 그 경로선 위에서 내 목적지와 가장 가까운 지점을 하차지점으로 추천.
   그 지점이 종점에서 120m 이내면 그냥 "팟장 목적지"로 합쳐서 부름(이름 혼동 방지)
3. 경로가 아직 없으면(폴백) → 미리 정해둔 고정 정류장(STOP_NAMES) 중 내 목적지에서 제일 가까운 곳

**도보시간 환산**: `walkTimeOf` (1183) = `거리(m) / 70` — 분속 70m 기준.

**중요한 설계 결정**: 최종 목적지(trunk)는 언제나 "팟장의 목적지"로 고정된다(`leaderDestOf`, 1188).
누가 더 먼 곳으로 합류해도 팟장 목적지를 밀어내지 않는다 — 그래서 합류 조건이 "누가 더 먼가"가 아니라
"팟장 경로 위, 도보 10분 이내인가"로 단순화된다.

## 5. 요금은 어떻게 나누나?

`calcFinalRouteAndFare`(1308), 확정 시점에 참가자 구성 기준으로 재계산.

1. **정차 순서 결정**: 각 하차지점을 기준 경로(출발지→팟장 목적지) 위에 투영해 진행거리(m) 순으로 정렬 → `stops` 배열
2. **총 요금 산출**:
   - 카카오모빌리티 길찾기 API가 실제 요금을 주면 그 값 그대로 사용(`isRealFare`)
   - 아직 안 받았으면 **포항시 택시요금 공고 기준 추정치**(`estimateFareMins`, 1299): 기본 4,500원/1.7km + 이후 128m당 100원 + 23~04시 심야 20% 할증. (시간운임 — 15km/h 이하 서행 시 30초당 100원 — 은 실시간 정체 정보가 없어 이 추정 함수엔 반영 안 함, 실제 API 응답 오면 그 값으로 바로 대체됨)
3. **구간별 배분**: 총 요금을 구간별 주행거리 비율로 나눔(`splitProportional`) — 정수 배분 후 나머지는 소수부 큰 순서대로 1원씩 배정해 합계가 총액과 정확히 일치하도록 처리
4. **사람별 배분**: 각 구간 요금은 "그 구간에 아직 타고 있는 사람 수"로 n분의 1씩 나눠 누적 — 즉 오래 타고 갈수록, 그리고 그 구간에 동승자가 적을수록 더 많이 냄(1393~1402)
5. **참가 전 미리보기**(`previewJoin`, 1414)도 확정 로직과 완전히 같은 계산을 미리 돌려서 보여준다 — 예전엔 "확정 전엔 어차피 바뀌니까"라며 단순 1/n으로 보여줬는데, 그러면 실제로 더 먼 사람이 참가 전엔 싸 보였다가 확정 후 훨씬 더 내는 문제가 있어서 지금은 항상 "지금 인원 기준 정확한 값"을 보여주도록 바꿈

## 6. 실시간 동기화는 어떻게 하나?

Supabase Realtime(Postgres 변경분 구독) 사용, `subscribePod`(979)/`subscribeHome`(신규, 홈 카드용).

- 팟 상세/채팅 화면: 그 팟의 `pod_participants`(참가자 입/퇴장)·`pod_messages`(채팅)·`pods`(상태 UPDATE)를 구독, 변경되면 화면 재렌더
- 홈 화면: 원래는 "재조회로 충분"하다는 설계였으나, 내 팟 인원수 카드만은 실시간이 필요해 별도 채널로 내 팟 하나만 구독하도록 최근 추가함
- 화면을 벗어나면 반드시 구독 해제(`unsubscribePod`/`unsubscribeHome`) — 안 그러면 채널이 계속 쌓임

## 예상 질문 대비 한 줄 요약

- **"매칭 알고리즘 뭐 쓰나요(ML인가요)?"** → 아니다. 규칙 기반(rule-based) 필터 5개 + 가중치 점수식. ML/추천엔진 아님.
- **"거리는 무슨 API로 재나요?"** → 직선거리는 자체 Haversine 계산, 실제 도로거리/요금은 카카오모빌리티 길찾기 API 사용.
- **"택시 여러 대로 안 쪼개나요?"** → 이 앱은 팟당 택시 1대(경로 1개) 고정 구조. 경유지(하차지점)를 여러 개 낀 하나의 경로로 처리.
- **"요금은 왜 공평한가요?"** → 실제 주행 거리 비율로 구간 나누고, 그 구간에 같이 타고 있는 사람 수로 n분의 1 — 짧게 탄 사람이 남의 몫까지 안 냄.
